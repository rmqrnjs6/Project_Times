> 최초 재구현 기록은 아래에 보존한다. 최신 로그인·MVC·CIA 변경은 문서 마지막의 추가 기록과 `security/DESIGN.md`, `security/VERIFICATION.md`를 확인한다.

기준일: 2026-11-06 (Asia/Seoul). 대상: `rmqrnjs6/Project_Times`, 작업 브랜치 `chore/import-project-template`.

## 재개 배경

사용자의 요청은 공유 대화를 문서로 보관하는 데 그치지 않고, 대화의 설계에 따라 프로그램을 다시 만들고 작업물을 GitHub에 올리는 것이었다. 이전 클라우드 소스는 확보하지 못했다. 이번 코드는 보존본을 근거로 새로 작성한 것이며, 과거 테스트·완성도 수치를 계승하지 않는다.

## 이번 변경

- Python 단일 템플릿에서 JSP·Java Servlet·Python·PostgreSQL의 세 서비스 구조로 확장.
- Java WAR 빌드, JSP 화면, JSON 요청 처리, Python 호출 시간 제한, PostgreSQL 저장·조회, Flyway 마이그레이션.
- 7축 참조 계산기: Decimal, 미확인 분모 유지, 하한·상한·판별 충족률, 모순 위험 역변환, 전문가 검토 전후 분리, 변화량·표시 함수.
- 원본 입력과 계산 결과·정책 버전 저장. 원문 사실을 판별한 결과로 표시하지 않음.
- 로컬호스트 포트, 입력 길이·형식 검사, 교차 출처 쓰기 차단, 보안 헤더, 비root 웹·Python 컨테이너, DB 볼륨과 자원 제한.
- 실행 안내, 구조 설명, 통합 테스트, 장애·재시작 점검, 별도 DB 백업·복원 스크립트, CI 구성.

## 문제와 수정

1. Windows의 8080 포트 바인딩이 거부됐다. 기본 포트를 18080으로 변경한 뒤 기동을 확인했다.
2. Python이 반환한 미검토 `null`이 Java Gson 응답에서 생략됐다. `serializeNulls()`를 적용하고 같은 통합 케이스로 재검증했다.
3. 읽기 전용 Python 컨테이너에 테스트 파일을 `docker compose cp`로 복사할 수 없었다. 읽기 전용 설정을 유지하고 표준입력으로 검증 코드를 실행하도록 변경했다.
4. Windows PowerShell 5에서 Docker의 진행 출력(stderr)이 백업 스크립트를 중단시켰다. 복사 구간의 출력 처리와 종료 코드 검사를 구분해 수정했다.

## 검증 범위

실행 환경: Windows에서 Docker Desktop 4.78.0 / Engine 29.5.3, Linux 컨테이너, Python 3.12, Java 21, Tomcat 10.1, PostgreSQL 17. 실제 Python 의존성 버전은 `verification/python-packages.txt`에 기록한다. Java 전용 단위 테스트는 아직 없으며, Maven 컴파일·WAR 빌드와 HTTP 통합 검증으로 확인한다.

Python 케이스는 `tests/test_scoring.py`, `tests/test_api.py`에 있다. 예를 들어 긍정 6·부정 2·미확인 2의 기대 결과는 60~80%, 판별 충족률 80%이다. 모순 위험 0.2~0.7은 종합 계산에서 0.3~0.8로 역변환한다. 전문가가 미검토인 검토 후 종합값은 0이 아닌 null이다. 음수·불리언 수량과 합계가 1이 아닌 가중치는 거부한다.

통합 케이스는 `scripts/integration_check.py`에 입력과 기대값을 명시했다. JSP 렌더링, 보안 헤더, Java→Python·DB 연결, 합성 한글 질문 저장·조회, 계산 실행 ID와 입력·결과 저장, null 보존, 400/403/413/415/422 오류 응답을 확인한다.

최종 실행 결과와 로그는 `verification/RESULTS.md`에 별도로 기록한다. 실패 당시 원본 로컬 로그와 빌드 로그는 `artifacts/`에 남기고 저장소에는 민감정보 없는 최종 검증 로그만 포함한다. DB 덤프와 `.env`는 업로드하지 않는다.

## 미구현·미확인

실제 AI·검색 API 호출, 원문 지지·반박 판별, 7축 각각의 전문 판별 엔진, 전문가 독립 검토·로그인·권한·실시간 공유·레이더 차트·10회 예산 제어·실행 중 작업의 체크포인트·재개는 구현하지 않았다. 유료 API 비용은 발생시키지 않았다. 자동화 브라우저의 버튼 조작·시각 레이아웃 검증, 운영 보안 감사와 부하 검증도 미수행이다.

DB 행의 재시작 후 보존을 확인하는 것은 실행 중 AI 작업의 자동 재개를 검증하는 것과 다르다. 백업 복원 행 수 비교는 전체 데이터 무결성·재해 복구 능력의 완전한 증명이 아니다. 전체 목표에 대한 측정 기준이 없어 완성도 백분율을 부여하지 않는다.

## 2026-11-06 추가: Spring MVC·로그인·CIA

사용자가 Mock 기반 로그인 검증, CIA 관점 외부 자료 예방, Spring Boot MVC와 상세 검토 가능한 설계를 요청했다. 직접 Servlet을 Spring Boot MVC 계층으로 전환하고 Spring Security의 실제 인증·CSRF·세션·역할 검사를 적용했다. 질문과 계산·자료에는 현재 인증 소유자를 저장한다. 기존 행은 삭제하거나 임의 계정에 귀속하지 않았다.

비밀번호 해시, 최초 계정의 비밀 설정 필수화, 로그인 예산·감사 저장, 실패 시 접근 차단을 구현했다. 외부 자료는 기본 거부하는 수동 텍스트 격리 접수만 허용하며 다운로드나 AI 분석을 시작하지 않는다. 백엔드 외부 통신을 격리하고 로컬 접속 진입점을 분리했다.

MockMvc와 실제 DB/HTTP 검증은 별도로 수행한다. 보안의 절대 보장이나 운영 준비 완료로 표현하지 않는다. 사용자 발급·MFA·외부 수집기·운영 배포 등 다음 단계는 추가 논의 대상으로 남긴다. 정확한 케이스·환경·실패와 수정·재실행 결과는 `security/VERIFICATION.md`에 기록한다.
