# 직접 검토 시작하기

기준일: 2026-11-06 KST. 실행 화면과 현재 구현한 동작을 직접 확인하기 위한 안내다.

준비 확인: `Prepare-Review.ps1 -NoOpen`을 실제 실행해 `/ready`의 status=ok와 로그인 페이지 HTTP 200을 확인했다. 로그인 안내가 Git 무시 대상인지 확인한 후 로컬 파일을 생성했다. 자동으로 브라우저를 열거나 사용자를 대신해 로그인하지는 않았다.

## 열기와 로그인

저장소 루트의 `REVIEW.bat`를 실행하면 서비스를 시작하고 준비 상태를 확인한 뒤, 브라우저 로그인 화면과 로컬 로그인 안내를 연다. Docker Desktop이 실행 중이어야 한다. 코드를 다시 빌드하거나 비밀번호를 변경하지 않는다.

- 실행 화면: http://127.0.0.1:18080/login (기본 포트)
- 로그인 안내: `artifacts/review/LOGIN.txt` — 이 PC에서만 보관하는 비밀 파일이며 Git에 업로드하지 않는다.
- 자동 창 열기 없이 준비만 할 때: `powershell -NoProfile -File scripts/Prepare-Review.ps1 -NoOpen`

로그인 안내는 `.env`의 최초 계정 설정을 사용한다. 이후 비밀번호를 변경했다면 변경된 비밀번호가 우선이다. 로그인 창에서 직접 입력하고, 안내 파일을 외부에 공유하지 않는다.

## VS Code에서 로그인 오류가 날 때

VS Code Simple Browser 대신 Edge 또는 Chrome의 일반 창에서 `http://127.0.0.1:18080/login`을 연다. 현재 서비스는 CSP `frame-ancestors 'none'`과 X-Frame-Options DENY로 프레임 삽입을 차단하므로 Simple Browser를 검토 환경으로 지원하지 않는다.

`cross_origin_rejected` 관련 수정(2026-11-06 KST): 기존 서버의 `Referrer-Policy: no-referrer`는 브라우저의 HTML 폼 POST에서 `Origin: null`을 유발할 수 있으나 출처 필터는 이를 거부했다. 앞선 수동 HTTP 검증은 정상 Origin을 직접 지정하여 이 충돌을 놓쳤다. 프레임 제한과는 별개의 서버 설정 문제다.

정책을 `same-origin`으로 변경했다. 외부 사이트로의 Referer 전송은 제한하면서 동일 출처 폼의 Origin을 유지한다. 출처 검사와 CSRF 보호는 유지하며 `null` 출처를 허용하지 않는다. 기존 로그인 탭을 닫고 주소를 다시 열거나 새로고침한 뒤 로그인한다.

검증: Java 47건 통과(실패·오류·건너뜀 0), 실행 서버의 응답 정책 `same-origin`, 동일 출처 로그인 HTTP 200 및 `/` 이동, `Origin: null` 요청 403을 확인했다. 브라우저 자체의 폼 제출을 자동화한 결과는 아니며 사용자 Edge에서의 최종 확인은 남아 있다. 원래 실패 요청의 헤더는 확보하지 못했다.

근거: [MDN Referrer-Policy — Origin에 미치는 영향](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy). 로컬 빌드 로그는 `artifacts/review/login-fix-build.log`에 보존한다.

## 수동 검토 기록 사용

새 화면은 새로고침 후 표시된다. 서버 재시작으로 세션이 사라졌다면 다시 로그인한다.

1. 검증 작업에 질문과 근거 조건을 입력하고 등록한다.
2. 목록에서 작업을 선택하면 상태와 원본 JSON·이력이 표시된다. AI 실행기가 없어 실행 상태는 대기다.
3. HTTPS 출처 주소, 원문 발췌, 내 해석, 지지/반박/미확인 판단을 입력하고 저장한다. URL은 참조만 저장하고 내려받지 않는다.
4. 잘못된 판단은 이유를 적은 새 기록으로 정정한다. 기존 원문·판단은 남는다.
5. 새로고침 후에도 기록이 남는지 확인하고, JSON 내보내기로 작업·상태 이력·근거 기록을 내려받는다. 내보낸 파일은 자신의 로컬 자료로 관리한다.

질문은 “이 자료가 질문의 주장과 직접 관련되는가?”처럼 넣고, 공유 가능한 짧은 원문만 사용한다. 본인이 입력한 수동 판단은 사실 인증이나 전문가의 독립 검토와 구분한다. 자세한 코드 설명과 검증 범위는 [수동 검토 기능 설명](verification/MANUAL_REVIEW.md)을 읽는다.

## 화면에서 확인할 순서

1. **로그인**: 올바른 정보로 검증 작업대가 열리는지 확인한다. 로그인 후에도 화면에 미구현 범위가 표시되는지 본다.
2. **서비스 연결 확인**: `Java · Python · DB 확인`을 누른다. 정상이라면 status=ok가 나온다. 이는 실제 AI 판별 성공이 아니다.
3. **질문 저장**: `검토용 질문 1`을 입력하고 저장한다. 저장 ID와 목록이 표시되고 새로고침해도 남는지 확인한다. 저장은 현재 로그인한 계정에 귀속된다. 과거 소유자 미지정 기록은 자동으로 귀속하지 않았다.
4. **참조 계산**: 기본 JSON을 그대로 계산한다. F는 긍정 6·부정 2·미확인 2이므로 하한 60.0%, 상한 80.0%, 판별 충족률 80.0%를 기대한다. E는 미검토(null)다. 산술 범위는 정답 확률이 아니다.
5. **미검토 처리**: E를 null로 둔 상태에서 `전문가 검토 후`를 선택해 계산한다. 종합값은 0점이 아니라 null이어야 한다.
6. **입력 오류**: F의 positive를 -1로 바꾸고 계산한다. 잘못된 입력으로 거부되고, 이전 성공 결과를 새 결과처럼 표시하지 않는지 확인한다.
7. **로그아웃**: 로그아웃한 뒤 작업대에 다시 접근한다. 로그인이 필요해야 한다. 반복 로그인 실패·서비스 중단 테스트는 평상시 검토에서 실행하지 않아도 된다.

검토용 질문·계산을 저장하면 실제 로컬 개발 DB에 기록된다. 이번 검토는 읽기 전용 시연 모드가 아니며, 유료 API 호출은 하지 않는다.

## ChatGPT 웹·앱에서 확인

같은 PC의 ChatGPT 데스크톱 앱에서 내장 브라우저가 연결돼 있으면 위 로컬 주소를 열어 함께 검토할 수 있다. 일반 Edge·Chrome에서도 열린다. 현재 세션에서는 내장 브라우저 연결 오류가 확인돼 자동으로 옆 창에 열지는 못했다.

이 주소는 인터넷 공개 주소가 아니다. 다른 기기나 ChatGPT의 클라우드 브라우저는 이 PC의 localhost에 접근할 수 없다. 외부 검토 주소와 호스팅은 아직 생성하지 않았다.

## 피드백 기록

`화면/기능 → 입력·누른 버튼 → 기대한 결과 → 실제 결과 → 수정 희망` 순서로 알려주면 현재 구현과 대조해 다음 변경을 논의할 수 있다. 검토 결과를 받기 전 기능 확대나 운영 공개를 확정하지 않는다.
