# Review and revision policy

1. Preserve original evidence and decisions; changes need a reason and a traceable commit or PR.
2. Separate verified facts from assumptions, interpretations, and unverified claims.
3. Review meaningful changes in a pull request before merging.
4. Passing CI confirms only the checks that ran, not overall correctness.
5. Never commit secrets, passwords, private user data, or real `.env` files.
6. Record test cases, environment, expectations, actual results, and logs before claiming tests passed.
