# 평가 작업대 통합 검증

확인일: 2026-11-11 (한국시간). 환경: Linux, Node.js 24.22.1. CI에는 Node.js 22를 지정했지만 해당 버전의 원격 실행 결과는 아직 확인하지 않았습니다.

## 범위와 결과

문제: MD 파일만 저장하면 사이트의 검색어 입력·모델 전달·결과 확인 흐름을 저장소에서 재현할 수 없습니다.

변경: Sites 버전 5 소스를 독립 모듈에 배치하고 루트 명령 → 빌드/테스트/미리보기 → 결과 확인으로 연결했습니다. 기존 앱·Docker·보안 파일과 기존 CI 작업을 교체하지 않습니다.

실행: `node scripts/workbench.mjs check` — 종료 코드 0. 화면 JS 구문 검사, 7개 자산이 포함된 Worker 빌드, 테스트 11건 통과. 원문 출력은 [실행 로그](workbench-check-2026-11-11.txt)에 있습니다. 모의 응답 테스트이므로 실제 공급자 연결 성공이 아닙니다.

별도 HTTP 확인: 루트 `start` 명령으로 빌드 후 127.0.0.1:5187에서 입력 화면과 `/api/integrations`의 200 응답을 확인했습니다. 가짜 환경 키와 위조 신원 헤더를 넣어도 로컬 미리보기는 설정 미등록 상태를 유지하며 `/api/solve`를 403으로 거부했습니다. 실제 공급자 호출은 없었습니다. 확인 후 테스트 서버를 종료했습니다.

## 기존 경로 보존과 미검증

기존 CI의 Python·Docker·인증 통합 작업은 내용을 유지하고 Node 작업만 추가했습니다. 기존 Spring/Python/DB 앱 코드는 변경하지 않았으며, 이번 실행에서 해당 전체 Docker 통합 검사를 재실행하지 않았습니다. 원격 CI 성공은 커밋 후 별도 확인이 필요합니다.

화면 소스는 이전 공개 버전에서 검증된 입력 → 파라미터 미리보기 → 평가 → 분석 흐름을 가져왔습니다. 이번 저장소 통합에서는 별도 브라우저 검사를 반복하지 않았습니다. 실제 API 키·수학 성능·D/E 어댑터·Spring 로그인 통합·SymPy/Lean 검증은 미완료입니다. Sites를 재배포하지 않았습니다.
